01Safety and about this manual

Safety first

Take every propeller off before you calibrate, test motors, change parameters on the bench or install firmware. One wrong parameter is enough to crash an aircraft, so save a backup before each session and change one thing at a time. Even during an AUTO mission, keep the radio control transmitter in your hands, ready to take over. Fly only where and how the law allows; in India that means the Drone Rules 2021 and the DGCA's Digital Sky requirements. The software comes without warranty under the GNU GPL v3, and the operator is responsible for every flight.

This manual covers Sarus Operation Planner 1.1.0 for Windows. The program is built on ArduPilot Mission Planner 1.3.83 and keeps every one of its screens, controls and keyboard shortcuts, so Mission Planner tutorials apply here too. What differs is the look, the way parameters are edited and protected (chapter 11), the airframe limits and in-flight alarm (chapter 11), more reliable communication with the aircraft, and where files are kept.

Conventions: on-screen names are in bold. Menu paths are written CONFIG → Full Parameter List. Keys are shown as Ctrl+P. Parameter names are in MONOSPACE.

02Product overview

Sarus Operation Planner is a ground control station (GCS): Windows software that connects to a drone's flight controller and lets you set up, plan, fly, monitor and analyse ArduPilot aircraft.

What you can do with it

Before a flight you can install or update the firmware on the flight controller, calibrate the accelerometers, compass, radio and ESCs, set flight modes and failsafes, and tune the aircraft: PIDs, TECS, navigation and the VTOL settings, down to any single parameter. Missions are planned on a map with waypoints, surveys, geofences and rally points.

In the air, the DATA screen gives you a live HUD, map, gauges and quick actions, and the program can speak mode changes, altitude and battery warnings. Afterwards you can replay the telemetry, download the flight controller's own log and analyse both. ArduPilot's simulator lets you fly without hardware, and optional equipment such as GPS, airspeed sensors, rangefinders, gimbals, OSD, CAN devices, ADS-B receivers and telemetry radios is set up from the same program.

Supported vehicles

Flight controllers: any board that runs ArduPilot, including Pixhawk-class boards (Pixhawk, Cube, Holybro, Matek, CUAV and others).

What is different from Mission Planner

LookSarus Dark (default), Sarus Light and the opt-in Sarus Glass themes, Sarus menu icons and the "Powered by Sarus Aerospace" badge. HUD and map colours are unchanged.
ParametersValues are taken exactly as typed: no recommended ranges, no clamping, no suggested parameter sets. Read-only values can be changed after confirmation. Every written value is re-read from the aircraft (chapter 11).
Parameter lockSetup changes need the owner's admin password, enforced by the program and by aircraft running Sarus firmware (11.3).
Airframe limits and alarmValues beyond what the airframe can do blink red, and a siren asks continue, hold or return when a mission is not going as set (11.4, 11.5).
ReliabilityReplies from the aircraft can no longer be lost when two requests wait at the same time (parameters, commands, missions).
CoexistenceInstalls beside Mission Planner with separate settings, logs, maps and updates.
PrivacyAnonymous usage statistics are off by default.
AirspaceNo Altitude Angel or other airspace service is included, so the program never restricts where you fly. The aircraft's own geofence and failsafes still apply, under your control.
Network safetyThe built-in web server accepts flight commands only from this PC; other devices on the network can still view telemetry.

04Installation

4.1 Download

Download the latest SarusOperationPlanner-x.y.z.msi from the Sarus releases page: github.com/LikhitS/SarusOperationPlanner/releases, or from the Sarus Aerospace website.

4.2 Install

  1. Double-click the downloaded .msi file.
  2. If Windows shows Windows protected your PC, click More info, check that the file is the one from Sarus, then click Run anyway. This appears until the installer carries a code signature.
  3. Read and accept the licence (GNU GPL v3), then click Next.
  4. Keep the default folder C:\Program Files (x86)\Sarus Operation Planner or choose another, then click Install and approve the administrator prompt.
  5. When Windows asks to install device drivers (for flight-controller USB ports), click Install. These are the same drivers Mission Planner installs.
  6. Click Finish. Start the program from the Start menu: Sarus Operation Planner.
Silent install (IT departments)

msiexec /i SarusOperationPlanner-1.3.83.msi /qn /norestart installs without questions. In a silent install, Windows adds only the USB drivers whose publisher is already trusted; ArduPilot boards on Windows 10/11 normally use the built-in Windows USB serial driver. Uninstall with msiexec /x and the same file, or from Windows Settings → Apps.

4.3 Next to Mission Planner

Sarus Operation Planner and Mission Planner can be installed on the same PC. Each has its own program folder, Start-menu entry, settings, logs, map cache and update channel. Installing or removing one does not affect the other. Only one program can use a given COM port at a time.

4.4 Updating

On start, the program checks the Sarus releases on GitHub. When a new version exists, it offers to update. The updater downloads only the files that changed and verifies each file's checksum. You can also check manually in HELP → Check for Updates, or install a newer .msi over the current one; settings are kept.

4.5 Uninstalling

Windows Settings → Apps → Installed apps → Sarus Operation Planner → Uninstall. Your logs, missions and settings in Documents\Sarus Operation Planner are kept; delete that folder by hand if you no longer need them.

6.2 Connect

  1. Plug in the flight controller (USB) or the ground telemetry radio, and power the aircraft.
  2. Choose the COM port (or TCP/UDP) and the speed in the top-right lists.
  3. Click CONNECT or press F12.
  4. The program waits for a heartbeat, then downloads all parameters (a progress window shows this). When it finishes, the HUD moves and the title bar shows the firmware version.

Click DISCONNECT (or F12 again) to disconnect. Ctrl+T connects without downloading the parameters (advanced). Stats… under the connection lists shows link quality, bytes per second and packet loss.

With several aircraft or components on one link, choose which one to control from the system-ID list that appears in the connection area.

07DATA – Flight Data screen

This is the screen you fly from. The HUD sits at the top left, the tabs below it and the map on the right; drag the dividers to change the proportions.

7.1 HUD (head-up display)

The HUD draws the artificial horizon with roll and pitch, plus heading, airspeed and ground speed (left tape), altitude (right tape), vertical speed, flight mode, armed state, GPS status, battery, link quality, distance to waypoint and current waypoint, plus warnings such as PreArm messages, EKF problems and low battery. HUD colours are those of Mission Planner.

Right-click the HUD for: Video (start a camera, MJPEG or GStreamer source, Herelink video, record HUD to AVI), Set Aspect Ratio, User Items (add any telemetry value to the HUD), Swap With Map, Ground Color, Battery Cell Voltage, Show icons and Russian Hud.

08PLAN – Flight Planner screen

Missions, geofences and rally points are created, loaded and sent from here. The map takes most of the screen, with the mission table along the bottom and the action panel on the right.

8.1 Making a mission

  1. Check Home Location (filled in from the aircraft when connected).
  2. Set the defaults: WP Radius, Loiter Radius, Default Alt, and the altitude frame (Relative, Absolute or Terrain). Tick Verify Height to use terrain data.
  3. Left-click the map to add waypoints. Drag a waypoint to move it.
  4. In the table, change each row's Command (WAYPOINT, VTOL_TAKEOFF, VTOL_LAND, LOITER_TURNS, DO_JUMP, DO_SET_SERVO, DO_CHANGE_SPEED…) and its parameters, latitude, longitude and altitude. The column headers change to explain the parameters of the selected command. Use the arrows to reorder and X to delete.
  5. Click Write (Ctrl+Shift+W) to send the mission to the aircraft, then Read (Ctrl+Shift+R) to confirm it. Write Fast (Ctrl+Shift+F) sends without waiting for each item.
  6. Save the mission with Ctrl+S; open one with Ctrl+O. Ctrl+Z undoes the last change.

The status bar shows total distance, distance between points, and an Alt Warn indication. Use Elevation Graph (right-click) to check terrain clearance.

11Parameters, the lock and airframe limits

Open CONFIG → Full Parameter List. Every parameter is shown with its value, units, named options where it has them, and a description. Sarus takes the value you type and nothing else: it never pulls a value back into a range, and it offers no ready-made parameter sets.

11.1 Buttons

11.2 How Sarus treats your values

SituationWhat Sarus does
A value ArduPilot would call unusualAccepted as typed. Sarus 1.1.0 no longer shows or applies ArduPilot's recommended ranges, and the spin box under the Options column no longer clamps to them. The only judgement on a value is your own airframe limits (11.4).
Read-only parameterA warning asks you to confirm. If you choose Yes, the value is sent.
After Write ParamsSarus re-reads every written value from the aircraft. If the aircraft limited, rounded or rejected a value, the window Values changed by aircraft lists it, and the table shows the value the aircraft actually uses.
Suggested valuesNot offered. Load Presaved and SETUP → Initial Tune Parameter, which write values the program proposes, are gone from Sarus.
What the firmware itself changes

We wrote every parameter of QuadPlane, Copter and Rover to the simulator and read it back, about 3,000 in all. The firmware kept a different value in only a handful of cases, and none of them is an ArduPilot preference that could be removed safely. Q_LOIT_ACC_MAX_M and LOIT_ACC_MAX_M are capped at what the maximum lean angle allows, because a multirotor tilted to 30 degrees can only accelerate sideways at g·tan(30°), about 5.66 m/s², without losing height. EK3_BCN_DELAY, EK3_FLOW_DELAY and LAND_THR_SLEW are stored in 8 bits and stop at 127. The firmware overwrites BARO*_GND_PRESS on its own, and MIS_TOTAL cannot be written at all. Some settings, Q_ENABLE, the frame class and the serial protocols among them, only take effect after a reboot and a refresh with F5. In each case Sarus shows you the value the aircraft actually holds.

11.3 The parameter lock

Anyone with Sarus can connect, read every parameter, plan and fly. Changing how the aircraft is set up needs the Sarus admin password, which only the owner holds. When you try a change, Sarus asks for the password once; after that, changes are unlocked until you press Lock parameters or close the program.

Needs the passwordStays open
Parameter writes from any page, loading a parameter file, Reset to Default, every calibration, reboot into the bootloader, firmware install, file writes over MAVFtp, receiver pairing, Lua scripting commands, MAVLink signing setupConnecting, reading parameters, planning and uploading missions, arming, flying, mode changes, plain reboot, downloading logs

The lock has two halves. Sarus itself refuses the change until the password is given. On aircraft running Sarus firmware (Sarus-2 or later), the aircraft refuses it as well: after the password, Sarus unlocks each connected aircraft with a signed, one-time code before the change is sent. Another ground station, an older copy of Sarus or a home-made tool cannot change the aircraft's setup without the password, even if it skips the program's own check. The aircraft reports each refusal in Messages as "Sarus: locked, ... refused".

Unlocking while armedRefused by the aircraft. Unlock on the ground; an unlock made before take-off stays valid in the air, so you can tune in flight.
Link lostAn aircraft locks itself again after 10 seconds without hearing the station that unlocked it, once disarmed. It never locks in flight. A reboot always locks it.
Two stationsAn unlock belongs to the station and radio link that made it. A second station, or the same station on a second radio, is still refused.
"Aircraft refused the unlock"Its firmware was built with a different admin key. Changes to it will not take effect.
Aircraft on ArduPilot firmwareOnly the program's half of the lock applies. Install Sarus firmware to lock the aircraft itself.
Lost passwordNobody can recover it. The owner keeps a spare password in a safe place for that reason. Without either, aircraft need firmware with a new key.
What the lock cannot stop

Someone with the flight controller on a bench can still flash other firmware through its USB bootloader. Protecting against that needs a secure bootloader, which is planned. Settings inside DroneCAN peripherals are not covered either.

11.4 Airframe limits

CONFIG → Airframe Limits holds what this airframe can physically do. The page shows only the boxes that apply to the connected vehicle; leave a box empty to skip that check, and press Save limits. The limits are stored for this flight controller only, by its unique ID, under Documents\Sarus Operation Planner\airframes.

VehicleLimits you can enter
Fixed wing and QuadPlaneStall speed, maximum airspeed, maximum climb and descent rate, maximum bank angle, maximum nose-up and nose-down pitch
Multirotor and VTOL hoverMaximum lean angle, maximum speed, maximum climb and descent rate
RoverMaximum speed, smallest turn radius

Any parameter that asks for more than the airframe can do blinks red: in the Full Parameter List as soon as you type it, and in a banner across the top of the window for as long as the aircraft holds it. The banner names the parameter and the limit; Details lists every one, and Hide hides it until the values change again. Sarus never changes or refuses the value. It understands the parameter names of both ArduPilot 4.6 and 4.7, in their own units (centidegrees, cm/s, degrees or m/s).

11.5 The in-flight alarm

During a mission (AUTO or GUIDED, armed), Sarus compares what the aircraft is trying to do with what it achieves: altitude, airspeed and position on the planned track. When one of them stays further off than the alarm settings on the Airframe Limits page, for longer than the set time, and is not getting smaller, a siren sounds and a window offers three choices.

Continue planThe mission goes on unchanged. The alarm stays quiet for 60 seconds.
Hold positionThe aircraft loiters where it is (QLOITER when hovering, HOLD for a rover).
Return homeThe aircraft returns to launch (RTL).
No answer in 15 secondsThe mission continues with the parameters as set. The alarm never changes anything on its own.

Defaults: altitude 15 m, airspeed 4 m/s, track 40 m, for 10 seconds. Take-off, landing and return legs are not judged, nor is airspeed before the aircraft is flying on its wings, because large differences there are normal. An error that is closing, such as a climb to a new altitude, does not raise the alarm. In the simulator, the alarm stayed silent through take-off, transition and climb, and sounded 11 seconds after the engine was cut in cruise.

11.6 Sarus firmware and its defaults

Sarus firmware comes in two lines with the same Sarus changes: one on ArduPilot 4.7.1, the newest stable release, and one on 4.6.3, the last release of the longer-proven 4.6 series. Install Firmware lists both and asks which to load. Firmware built with the owner's parameter set uses it as its defaults, so a new board, a parameter reset or a firmware install starts from the owner's values. Sensor calibrations are never part of that set; every aircraft still needs its own.

Good practice

Save to file before you change anything. Change a few values at a time. After a tuning session, save again with a descriptive file name and date, and press Lock parameters before you hand the laptop to someone else.

12SIMULATION

The simulator runs ArduPilot's real firmware (SITL) on your PC, so you can fly without any hardware. We use it for training, for rehearsing missions and for trying out parameter changes before they go near an aircraft.

  1. Drag the Home Location marker to where you want to fly, and set the heading.
  2. Choose a vehicle: Plane, Multirotor, Helicopter or Rover. For a QuadPlane, open the advanced options and choose a quadplane model.
  3. The firmware is downloaded and started; the program connects automatically.

Advanced options: Model, Sim Speed, Wipe (reset parameters), Extra command line, and swarm modes (several simulated aircraft).

15QuadPlane (VTOL) quick-start workflow

A suggested order for setting up a new QuadPlane. Props off until step 10.

  1. Firmware: SETUP → Install Firmware → Plane.
  2. Connect over USB (115200) and let parameters download.
  3. Enable QuadPlane: set Q_ENABLE = 1 in the Full Parameter List, Write, reboot the board, press F5. Set Q_FRAME_CLASS and Q_FRAME_TYPE, Write, reboot.
  4. Outputs: SETUP → Servo Output: assign motors 1–4, aileron, elevator, rudder and throttle functions; check reverse settings.
  5. Calibrate: Accel Calibration, Compass, Radio Calibration. Calibrate the airspeed sensor (Optional Hardware → Airspeed).
  6. Flight modes: include QHOVER, QLOITER, FBWA and a return mode (RTL/QRTL).
  7. Failsafes: radio, battery and GCS failsafes, with VTOL-appropriate actions.
  8. Motor Test at 5%: order and direction for each VTOL motor; check surfaces move correctly in FBWA by hand.
  9. Save a parameter file as your baseline.
  10. First flight: follow the Sarus Field Test Checklist (QHOVER → QLOITER → transition → TECS check → small AUTO mission with VTOL_TAKEOFF and VTOL_LAND).
  11. Tune with CONFIG → Extended Tuning (TECS), QP Extended Tuning, and the Full Parameter List; review logs after each flight.

Telemetry logs and DataFlash logs

The telemetry log (.tlog) holds what the ground station received over the radio and can be replayed on the DATA screen. The flight controller writes its own DataFlash log (.bin), at full rate and with far more detail; download it after flight (DATA → DataFlash Logs) and open it with Review a Log to plot values, or use Auto Analysis.

17Troubleshooting

ProblemWhat to check
No COM port in the listCable is a data cable; drivers installed (reinstall Sarus); try another USB port; check Windows Device Manager.
"No heartbeat" / connection timeoutCorrect port and speed (USB 115200, SiK 57600); the port is not used by Mission Planner or another program; radios are paired and powered.
Parameter download stopsWeak radio link: move closer or use USB, or reduce telemetry rates (CONFIG → Planner). Press F5 to retry.
Cannot armRead the PreArm message on the HUD or in the Messages tab and fix its cause; never disable arming checks to fly.
"Values changed by aircraft"The firmware limited or rejected a value, or the aircraft is locked. The table shows the real value. See 11.2 and 11.3.
Password asked for every changeExpected while locked. Type the admin password once; changes stay unlocked until you press Lock parameters or close Sarus.
"Sarus: locked, ... refused" in MessagesThe aircraft refused a change because this station has not unlocked it. Unlock again while disarmed; check that only one station is connected.
Red banner at the topA parameter asks for more than the airframe limits allow. Press Details, then fix the parameter or the limit (11.4).
Firmware page emptyInternet connection needed; disconnect from the aircraft first.
Map is greyNo internet and no cached tiles for that area. Prefetch maps before going to the field (PLAN → right-click → Map Tool → Prefetch).
"Windows protected your PC"See 4.2. Appears until the installer is code-signed.
Blurry textWindows display scaling above 100%. Same as Mission Planner.
